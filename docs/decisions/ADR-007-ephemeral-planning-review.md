# ADR-007 — Explicit planning intent, ephemeral review and workflow revisions

**Status:** Accepted for Sprint 06, issue #15; extended for Sprint 07, issue #17. **Date:** 2026-10-21. Extends ADR-004/005; ADR-006's strict persistence projections and normal-document gate are unchanged.

## Decision

The worker's manual state has an explicit SOLO/TOGETHER mode independent of nickname selection. New workers/reset start SOLO with no review or track claims. A first plan preserves a deliberate current mode selection. Editing the same movie/cinema/date/time preserves that selection; replacing any of these four fields starts SOLO. Saving a plan explicitly clears both tracks as the UI explains. Hall edits also invalidate both tracks, but keep the same-night intention. No intent/review is saved in local/session storage or inferred from a restored draft.

SOLO rejects every B manual mutation at the coordinator, even a correctly authenticated message. TOGETHER enables a separate B flow without requiring a nickname or proving account identity. Switching off clears only B's local inputs, checks and binding after explicit confirmation when B has input/history. UI confirmation also covers its unsaved B fields. A's fields/checks/context remain. A missing B history requires no extra confirmation. Every mode transition advances the existing B epoch; selected identity changes and plan/reset retain their epoch invalidation. The B component remounts on epoch change, so an old unsaved form cannot appear for a replacement buddy or plan.

Preflight reuses the existing own-input forms. A complete plan/hall, matching entered showtimes, entered seats and no unresolved per-role problem are required before **REVIEW_PLAN**. Review records only an ephemeral local acknowledgement time, never website acceptance or a hold. ACCOUNT/SHOWTIME/SEATS/REVIEW/DONE still require exact order and cannot start without a current preflight. Review and self-reports expire after 15 minutes independently. Edits, problem/reset/unbind/binding changes, tab invalidation, consent revocation and buddy changes invalidate the shared review. B-only changes preserve A's already justified own checks; new acknowledgements wait for the revised preflight. The overview always labels these as user reports, never CONFIRMED. A/B comparison claims require review. Unsaved local edits mark the review as needing saved input and block this document's next own steps; they do not overwrite the shared committed plan.

Every panel manual mutation uses a strict **WORKFLOW {generation, revision, buddyEpoch, command}** envelope. The monotonic manual revision advances on state mutations and evidence invalidation; every new command compares all three counters immediately before mutation, after Chrome/storage awaits. A stale mutation is refused and the client refreshes only, never retries it. Duplicate clicks/reviews/acks cannot advance the state twice. Earlier unwrapped or B_COMMAND manual mutations are refused; parsing the old shape only enables a safe rejection. Popup and fixture cannot send WORKFLOW or see its state. Authenticated RESET retains the synchronous reset barrier; queued operations and delayed B messages remain guarded. The offline manual coordinator enforces the same mode/review rules, without shared storage.

## Effects and limits

This is a local protocol change within a single versioned bundle, not a migration of stored records or a remote transaction protocol. Saved nickname and five-field film-draft schemas remain v1. Worker/browser lifecycle never restores intent, review, seats, checks or context. No manifest permission is added: exactly sidePanel + storage. No automatic navigation, booking, retry, cancellation, rollback or Undo booking exists. **Review** means examining locally entered planning data. **Reset/again/clear** changes only local assistant data; it cannot undo a real reservation or cancel a Movie Pass subscription.

Unit/worker races, renderer keyboard/clipboard/announcer and real Chrome two-panel/worker tests are included. Actual platform execution is recorded separately in [feasibility](../feasibility.md); G0 live Vue remains NOT PASSED and human Mac/VoiceOver acceptance follows delivery.

## Sprint 07 extension — atomic first input, no persistence change

PLAN accepts optional strict `initialSeats: { A, B? }` using the existing intended-seat schema. The coordinator rejects B seats in SOLO or an unrelated-night replacement before mutation. A new plan may atomically enter its initial active seats/showtime; these remain own input, not review or account evidence. Existing separate MANUAL_DETAILS edits and all five ordered checks remain. WORKFLOW counters still wrap the entire mutation.

Technical view changes keep mounted forms alive. A passive worker replacement may preserve only already dirty, uncommitted film/A text in that open document as a labelled concept; it sends nothing automatically and restores no committed plan, seat, review, selection, mode or evidence. B is cleared on generation/epoch change, including the new initial B fields. Explicit reset/reconnect clears these local fields too. No retention schema/key, manifest permission or new persisted state is introduced. The self-test owns separate coordinators/documents and never dispatches into the real workflow.

Background GET_STATE/BUDDY_READ uses a separate coalesced read barrier so polling never disables a focused user control. A user mutation supersedes a pending read; a document-local operation counter drops its late snapshot/error without overwriting the mutation, releasing its busy guard or replaying anything. Mutations retain the existing exclusive busy guard and worker-side generation/revision/epoch checks. This changes no trust or persistence boundary.

## Sprint 08 — explicit clears override draft preservation

A newly observed remote worker with resetVersion > 0 has already processed an explicit clear, possibly from another panel: local film/A draft fields are cleared too. Passive worker replacement with no explicit reset may still preserve dirty, uncommitted A fields as concept only. Accepted canonical input/reset changes within one worker are reflected in the own-input form, so Begin A opnieuw does not silently retain a dirty old seat. Ordinary polls with unchanged canonical fields, technical view changes and B-only changes do not erase A. No new counter, wire/storage schema, persisted evidence or permission is introduced.
