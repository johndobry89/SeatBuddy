## Decision paths

**A — preferred, permission first.** Obtain written clarification or an official supported interface for manually triggered, read-only user-visible showing/category/availability data. Clarify freshness, accessibility and per-person post-pass costs; never infer zero from a ticket legend. Only after actual permission/technical evidence, request separate owner authorization for the minimal scoped permissions and implementation. Any future provider fails closed on changes/missing/expired data and hands booking back to the official flow. A/B contexts remain independently verified; no automatic hold/checkout/payment/cancellation.

**B — no supported permission/source.** The shipped manual shell offers only the official link and short separate-session / ZERO EXTRA reminders. This does not demonstrably beat a bookmark and two ordinary tabs. If no real-task improvement is measured, **STOP / pivot**. More forms, checklists or fake features do not resolve this gate.
